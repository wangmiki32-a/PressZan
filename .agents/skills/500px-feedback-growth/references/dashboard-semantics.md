# Dashboard 统计语义

Dashboard 只消费事件日志重建的聚合状态，不保存业务状态，也不反向修改事实。

## 五个主区块

1. 当前任务：最近不晚于当前时间且产生覆盖事实的 `daily_task_id`，显示覆盖摄影师、确认点赞、确认评论、跳过和状态。
2. 最新反馈扫描：按 `(occurred_at, scan_id)` 取最新 `feedback_scan_completed`，显示完成作品数、新 pair、反馈摄影师和反馈分。
3. 滚动 30 天表现：显示触达次数、覆盖摄影师、有反馈摄影师、原始反馈分和未反馈触达。
4. 关系分层与排行：固定显示 verified、promising、dormant、new；排行先按有效反馈分，再按原始累计分。
5. 策略配额：计划固定为 `120 exploit_first / 60 new / 20 retest`；实际值按点赞或跳过产生的首次摄影师覆盖计数，同时显示缺口和回填。

旧 100 赞或旧 200 覆盖任务继续出现在已完成历史中，但 cycle、双 review、观察窗口和延迟不再是主视图。

## 扫描完整性

- 完整启动扫描要求本人最新 3 张全部位于 `completed_photo_ids`，且没有 `scan_issue`。
- 首次完整出现的作品只建立 baseline；`baseline_photo_ids` 不贡献反馈分。
- 部分完成时状态必须是“数据不完整”，并列出缺失作品；不得显示为“0 反馈”的完整扫描。
- `new_feedback_points` 按新 pair 逐张计数。同一摄影师在 3 张分别产生新点赞可以贡献 3 分，因此反馈分不等于独立摄影师数。

## 指标定义

| 指标 | 单位与计算 |
|---|---|
| 覆盖摄影师 | 点赞与跳过事件中不同 `photographer_id` 的并集 |
| 触达次数 | `outgoing_like_confirmed` 数；同一摄影师不同日触达分别计数 |
| 有反馈摄影师 | 最近 30 天 `feedback_points_30d > 0` 的摄影师数 |
| 原始反馈分 | 归到触达的新 pair 数之和；单次触达最多 3 分，累计不封顶 |
| 未反馈触达 | 当前仍标记 `unanswered=true` 的触达数 |
| 每 100 次触达反馈分 | `100 * 最近 30 天反馈分 / 最近 30 天触达次数` |
| 有效反馈分 | 原始正反馈按 30 天半衰期衰减后求和并封顶 12 |
| 有效未反馈触达 | 未反馈触达按 30 天半衰期衰减后求和 |

“每 100 次触达反馈分”允许超过 100，因为一次触达最多贡献 3 分。它不是摄影师回馈率，不能添加百分号或用“转化率”命名。

## 分层

- `verified`：最近 30 天至少 3 个反馈分。
- `dormant`：历史累计至少 3 次触达且最近 30 天 0 分。
- `promising`：最近 30 天 1-2 分，或历史有正分且未进入 dormant。
- `new`：其余摄影师。

分层判断顺序是 verified、dormant、promising、new。Dormant 只有最后一次未反馈触达满 7 天后才可进入 retest。

## 时间归属与 legacy

- 反馈分的发现时间取下一次最新 3 张启动扫描时间；平台未提供真实点赞发生时间。
- 新触达在发生当天进入未反馈样本；后续扫描发现正反馈时，同一触达转为 1-3 分正样本，不同时保留正负。
- 旧 success/failure/open episode 各映射一次到其最后触达，旧 cycle/review 只读兼容，不重复计分。
- 历史任务的覆盖、点赞、评论和完成状态保持原样。

## 发布前检查

1. 五个主区块顺序正确，历史任务仍可读。
2. 不完整扫描显示“数据不完整”，不伪造缺失作品为零。
3. 每 100 次触达反馈分无百分号且允许超过 100。
4. 关系排行同时展示有效分和原始分，有效分不超过 12。
5. 页面默认 `data-theme="light"`，主题按钮可切换深色并返回浅色。
6. 桌面与不超过 720px 的窄窗口无页面级横向溢出；宽表只在自身容器滚动。
7. 不展示事件模型无法重建的层级变化、真实点赞时间或严格因果。
