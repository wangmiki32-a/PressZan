# 项目知识缺口

本文件只记录会影响未来安全性、算法判断或执行可靠性，且当前仍缺少真实证据的问题。普通待办和一次性故障不进入这里。

| 缺口 | 当前已知 | 需要的证据 | 关闭条件 |
|---|---|---|---|
| 跨机器串行交接的真实可靠性 | clean clone、动态路径、Git-backed runs 和 doctor 已有自动验证；尚未由第二台机器完成真实批次 | 朋友 clone、登录同账号、doctor、最新 3 张扫描、点赞、提交并由原机器 pull 后重建的完整证据 | 两台机器串行完成一次交接，期间无重复动作或状态漂移 |
| 安全暂停的作用域与显式解除语义 | `safety_paused` 能阻止同 checkpoint 继续写入；已确认无 active run 时 `status` 仍可能展示历史 `paused_reason`，而当前任务可已完成 | 同 run 恢复、新 run 启动和 Dashboard/status 的作用域测试 | schema 或聚合模型明确区分 active pause 与 historical warning，且测试覆盖展示和 gate |
| 即时反馈积分是否稳定 | 已有一次完整 3/3 扫描发现 35 个新 pair、16 位反馈摄影师和 19 个反馈分，证明单轮 0-3 分链路可工作；仍只有一个新模型样本 | 多个任务的完整 3/3 扫描、不同层级触达、0-3 分反馈和未反馈样本 | 样本足以比较每 100 次触达反馈分、分层与 `120/60/20` 配额，并能据此保留或调整阈值 |
| 只读 observation 的批量写入效率 | 当前公开 CLI 按单事件追加；大列表可用每批最多 10 位降低浏览器超时，但进程调用和日志体积仍偏大 | 一个带 schema 校验、幂等键和原子追加语义的 `observe-batch` 原型及性能测试 | 批量命令在不延迟互动 checkpoint、不改变 sealed 事实语义的前提下显著减少执行时间和日志开销 |
| 评论履约率的精确可重建性 | `outgoing_comment_confirmed` 能证明新增评论可见，但现有 schema 无法区分本次新增评论与本人相同评论已存在而跳过 | 为“相同本人评论已存在”提供稳定、无隐私泄露的可见状态证据和事件语义 | 不改变外部行为的前提下，sealed logs 能确定性重建两种结果；此前 Dashboard 只展示确认评论事实，不声称精确履约率 |

## 维护规则

- 新证据必须来自 sealed 日志、页面确认或可复现测试，不能凭印象关闭缺口。
- 关闭缺口时，把稳定结论迁移到 `AGENTS.md`、架构、运行手册或 ADR，并在此删除对应条目。
- 不记录候选名单、账号隐私、preview ID、run ID 或单次页面截图细节。
