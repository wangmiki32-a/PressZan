# 项目知识缺口

本文件只记录会影响未来安全性、算法判断或执行可靠性，且当前仍缺少真实证据的问题。普通待办和一次性故障不进入这里。

| 缺口 | 当前已知 | 需要的证据 | 关闭条件 |
|---|---|---|---|
| 连续覆盖 200 位并逐赞评论的限频风险 | 已完成单 run 100 个确认点赞，其中规则切换后的 15 次点赞均成功评论；尚未验证 200 位覆盖规模 | 至少一次 200 位运行的页面读回、耗时、评论确认和风险事件 | 完成真实 200 位运行，或观察到平台限频阈值并写入安全规则 |
| 单次 preflight 的 200 位候选充足度 | 历史扫描可观察到超过 100 位摄影师，但有效候选受页面失效、评论链长度和层级约束影响 | 新流程的 preview 数、运行时跳过数和重新播种次数 | 连续多个自然日稳定覆盖 200 位，或形成可验证的候选扩展策略 |
| 长时间 Chrome 会话稳定性 | 已知弹层、评论区和连接会出现异步空白或重连问题 | 单 run 的连接中断次数、恢复点和重复动作检查 | 同 run 中断恢复被真实验证，且没有重复点赞或状态漂移 |
| 跨机器串行交接的真实可靠性 | clean clone、动态路径、Git-backed runs 和 doctor 已有自动验证；尚未由第二台机器完成真实批次 | 朋友 clone、登录同账号、doctor、最新 3 张扫描、点赞、提交并由原机器 pull 后重建的完整证据 | 两台机器串行完成一次交接，期间无重复动作或状态漂移 |
| 安全暂停后的显式解除语义 | `safety_paused` 能阻止同 checkpoint 的继续写入，但事件 schema 没有独立的 recovery/cleared 事件 | 一次真实安全暂停、人工恢复与同 run/新 run 的完整日志 | 明确并测试暂停解除协议，确保历史暂停不会永久污染当前状态，也不会被静默忽略 |
| 即时反馈积分是否稳定 | 历史 episode 已映射为初始分数，但最新 3 张增量扫描尚未形成多个真实周期 | 多个执行日的完整 3/3 扫描、不同层级触达、0-3 分反馈和未反馈样本 | 样本足以比较每 100 次触达反馈分、分层与 `120/60/20` 配额，并能据此保留或调整阈值 |

## 维护规则

- 新证据必须来自 sealed 日志、页面确认或可复现测试，不能凭印象关闭缺口。
- 关闭缺口时，把稳定结论迁移到 `AGENTS.md`、架构、运行手册或 ADR，并在此删除对应条目。
- 不记录候选名单、账号隐私、preview ID、run ID 或单次页面截图细节。
