# 200 位摄影师覆盖与逐赞评论设计

## 目标

从下一次新运行开始，一次 Asia/Shanghai 自然日任务必须处理恰好 200 位不同摄影师。处理每位摄影师时只检查主页当前第一张作品：未点赞则确认点赞并留言 `👍👍👍`；已点赞或作品不可读则记录跳过。点赞数是处理结果，不再是完成条件。

## 完成语义

- `covered_photographers` 是当日 `outgoing_like_confirmed` 与 `candidate_skipped` 中不同 `photographer_id` 的并集。
- 同一摄影师每天只计一次覆盖，也只处理第一张作品；不再安排 verified 第二赞。
- 新运行仅在 `covered_photographers == 200` 时允许 `completed`，不得产生第 201 位。
- 候选耗尽、安全暂停或日界线到达时可以少于 200 位封存为未完成，未完成额度不结转。
- 历史 sealed run 的 `completed` 状态保持有效；旧 100 赞任务不按新合同反向改判。

## 评论语义

- 每个 `not_liked -> liked` 确认后，在同一作品提交一次 `👍👍👍`。
- 提交前若可见当前账号已存在完全相同评论，不重复提交；否则只在评论可见后记录 `outgoing_comment_confirmed`。
- 评论区不可用、提交后状态不明确或账号不匹配时记录 `safety_paused` 并停止。
- 历史点赞和本次规则启用前的点赞不补写评论。

## 选择与预览

Preflight 最多计划当天尚未覆盖的摄影师数。候选按当前分层和 Thompson Sampling 排序，200 位目标的默认桶为 `112 exploit_first + 50 retest + 38 new`；桶不足时由其他首赞候选补足，但不降低“200 位不同摄影师”和“每人一次”约束。

## Dashboard 与兼容性

Dashboard 把“覆盖摄影师”作为任务进度主指标，确认点赞和确认评论作为结果指标。历史 Tab 由日志中的完成状态决定，并同时显示覆盖、点赞、评论和跳过；旧日志无需迁移或修改。

## 验证

- Selector：200 个唯一候选、无第二赞、桶分配、候选不足。
- CLI：点赞与跳过共同累计覆盖、完成必须恰好 200、第 201 位被拒绝、跨日清零、旧完成日志仍有效。
- Dashboard：进度以覆盖 200 为目标，历史完成状态兼容旧任务。
- Skill contract：第一张、200 位、`👍👍👍`、逐赞评论和硬停止规则一致。
