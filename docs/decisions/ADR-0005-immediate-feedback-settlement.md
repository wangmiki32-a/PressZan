# ADR-0005：最新三张增量扫描与当日即时结算

> 修订说明：本 ADR 的跨日恢复边界已由 [ADR-0006](ADR-0006-cross-day-active-run.md) 替代；即时结算模型保持不变。

- 状态：Accepted
- 日期：2026-08-19
- 覆盖：新运行的冻结 5 张、双回顾和 72 小时 episode 结算流程

## 背景

旧流程需要点赞前冻结 5 张作品、逐张 baseline，并在结束后等待两次只读回顾和各 episode 到期。科学性较强，但一个周期跨越数日，调度、恢复、状态和 Dashboard 成本过高。用户要求保留“奖励常反馈、拓展新人、逐步放弃不反馈者”的方向，同时让当日任务立即收敛。

## 决定

新运行采用以下模型：

1. 每次启动先完整扫描本人主页最新 3 张公开作品。
2. 某张作品首次完整扫描只建立 baseline；后续扫描中每个此前未见的点赞 pair 计 1 个反馈分，并归到该摄影师扫描前最近一次触达。单次触达最多 3 分。
3. 新触达在当天封存时立即成为未反馈轻负样本；后续扫描发现正反馈时，同一触达改为正样本，不保留重复负样本。
4. 原始反馈分累计不封顶；选择使用 30 天半衰期衰减的有效分并封顶 12。
5. 分层使用最近 30 天原始事实；配额固定为 `120 exploit_first / 60 new / 20 retest`。
6. 状态继续使用 append-only Markdown 事件日志；不引入 mutable JSON、SQLite 或数据库摄影师表。

新运行不创建 cycle、未来 review Automation 或 72 小时 episode。旧事件保持只读兼容，不重写 sealed logs。

## 被拒绝方案

- 保留旧双回顾，仅缩短等待时间：仍需未来调度和跨日恢复，不能实现当日收敛。
- 每次扫描全部历史作品：浏览器成本和 token 消耗过高，且超出用户指定的最新 3 张范围。
- 用 mutable JSON 或数据库直接保存摄影师分数：会形成第二事实源，降低可审计和可重建性。

## 后果

- 当日任务结束即可得到完整覆盖、触达和未反馈状态；无需等待未来任务。
- 正反馈只能在下一次启动扫描时被发现，因此 `feedback_first_seen_at` 是观察时间，不是平台真实点赞时间，也不能证明严格因果。
- 作品离开最新 3 张后不再被主动扫描；模型用低成本近似换取更简单的运行和恢复。
- 同一轮 3 张都出现某摄影师新点赞时计 3 分，可快速进入 verified。
- 不完整扫描必须显示“数据不完整”，不能把缺失作品解释为零反馈。

## 验证

Store、analytics、selector、CLI、Dashboard、repository state 和 skill contract 测试覆盖事件校验、首次 baseline、0-3 分计分、正负去重、分层、有效分上限、`120/60/20`、legacy 映射和离线展示。桌面与窄窗口另做视觉 QA。
