# ADR-0002：一次运行完成当日剩余点赞任务

- 状态：Accepted
- 日期：2026-08-13
- 适用范围：Skill 公开入口、候选计划、run 生命周期和恢复

## 背景

初版把每日 100 个点赞拆成四次公开的 25 赞调用。该结构要求用户重复启动、复制审批参数并人工跟踪进度；每次重新进入也增加页面读取和状态漂移机会。Append-only checkpoint 已能在每个动作后提供恢复证据，因此公开分批不再承担安全职责。

## 决定

1. `$500px-feedback-growth` 无参数即恢复或开始当日任务。
2. 一次显式启动持续完成当天剩余额度，目标为当日累计 100 个确认点赞。
3. 一个 run 持续到 100、安全暂停或候选耗尽；普通中断恢复同一 run。
4. 首次候选审批仍保留 digest、expiry 和 quota snapshot，但用户只回复“确认执行”，内部 ID 由 `latest-preview` 解析。
5. 每个动作仍立即 checkpoint；不因单次运行目标变大而集中回填。
6. 旧的四个 25 赞 sealed logs 保持不可变并继续支持重建。

## 理由

- 用户入口只有一个，减少重复授权和命令错误。
- 运行生命周期与“每日最多 100”的业务边界一致。
- 恢复安全来自逐动作 checkpoint，而不是人为切分 run。
- 内部审批证据不需要成为用户操作负担。

## 后果

- Preflight 需要按当天剩余额度计划最多 100 个动作。
- 连续运行时间更长，平台限频和 Chrome 连接稳定性需要真实验证；硬停止规则优先于完成 100。
- 候选不足时允许提前结束，但不能降低至少 80 人、单人上限或 verified 第二赞规则。
- Dashboard 的“完成 100 才进入历史”规则不变。

## 验证

- Selector 默认计划当日 100，并按已有进度缩减。
- CLI 测试覆盖 0→100、37→63、单 run 100 和旧四 run 重建。
- Skill contract 拒绝公开 25 分组和 `run --approve <preview_id>`。
- 首次真实单 run 的风险与恢复证据记录在 `docs/knowledge-gaps.md`。
